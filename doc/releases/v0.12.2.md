# v0.12.2

## Automatic managed-file refresh

`lgtm update` now refreshes registered LGTM installations using the newly
installed binary. The refresh covers shipped rule files, managed guidance,
installed Claude/Codex hooks, generated Codex execpolicy, Pi extensions, and
installed Pi package/LSP configuration. Both project and global installations
are covered; rules-only installations are tracked too.

An already-current update also refreshes managed files. If you replace a binary
outside the updater, run `lgtm refresh`. `lgtm refresh-pi` remains an alias.

## Preservation and safety

- Do not redetect or rewrite repository policy, required commands, or execpolicy
  source configuration during refresh.
- Preserve unrelated settings, custom files, customized/repointed Pi extensions,
  edited Codex guidance/execpolicy output, and owner text around managed blocks.
- Back up edits to shipped rule filenames before replacing them, as init already
  does. Backup collisions fail visibly without overwriting owner content.
- Do not recreate removed managed files or removed hook events. Deliberately
  disabled integrations stay disabled.
- Restrict updates to registered installations associated with this executable;
  reject unsafe symlinks and malformed registrations. Registry traversal and the
  updater subprocess are bounded.
- If refresh fails after installation, the binary remains upgraded. Repair the
  reported problem and rerun `lgtm refresh`; do not assume every installation was
  refreshed after a failed command.

## Upgrade from v0.12.1 or earlier

Those versions have no installation registry or post-update refresh. After the
first binary upgrade, register existing installations once with their original
init command:

```sh
lgtm update
# Run the appropriate command once in each existing installation:
lgtm init
lgtm init --agent codex
lgtm init --agent pi
# Global installations:
lgtm init -g
```

Do not run all commands indiscriminately: register only adapters you use. For
rules-only installs, retain `--rules-only`. New init and verified Pi session
starts register installations automatically. LGTM does not search your disk for
unregistered repositories. Future upgrades refresh tracked installations without
per-repo reinitialization.

Reload or restart running agent sessions after an update: replacing files cannot
replace extensions or settings already loaded in memory. Automatic refresh does
not establish native UI approval authority. The pending native Pi/Claude approval
and cancellation smoke checks and generated-extension diagnostics documented in
v0.12.1 remain unresolved.

## Validation and rollback

Regression coverage includes project/global and rules-only refresh, binary
replacement, backup preservation, disabled hooks/files, owner settings and
policy preservation, generated Codex output, malformed registrations, and unsafe
symlinks. The release workflow runs locked tests on Linux and Intel macOS before
publishing checksum-protected binaries.

To roll back, reinstall v0.12.1 and restore required previous managed content
from backups or version control. An older binary does not understand the refresh
command; it will not automatically undo updated files. No new dependencies or
repository policy migrations are introduced. The private installation registry
is stored under `$HOME/.local/state/lgtm/pi-installations/`.
