# v0.14.1 — 2026-10-19

This release fixes a packaging defect in v0.14.0. That binary did not carry the
standalone Jev auto files. Updating a fresh server therefore did not install the
router or its gate-notice helper.

## What changed

The binary now embeds both files and installs this personal Pi extension:

```text
~/.pi/agent/extensions/jev-auto/index.ts
~/.pi/agent/extensions/jev-auto/jev-auto-gates.ts
```

Every init mode, `lgtm refresh`, and the managed-file refresh after `lgtm update`
can install the pair. No source checkout, manual copying, project registration,
or existing global LGTM hook is needed. An already-current pinned update also
runs this installation. `update --check` and `init --dry-run` write nothing.

A private receipt records the installed source hashes. Later updates replace
only recognized files. Custom edits are preserved. Refresh preserves files that
you removed after installation; explicit init can restore a recognized bundle.
The receipt is cooperative ownership state, not protection against the HOME owner.

## Upgrade

```sh
lgtm update
```

Run `/reload` in each running Pi session, or restart Pi. Then use
`/jev-auto status`. Routing starts at a model-context step, not in the updater's
terminal output. Runtime classification still needs an authenticated provider;
the CLI installer makes no model or provider calls.

An exact current manual pair can be adopted without changing its source bytes.
Only a complete, exact current legacy flat pair is migrated automatically. Its
backups go outside Pi extension discovery, under
`~/.local/state/lgtm/jev-auto/legacy/`. Unknown, partial, or edited legacy files
cause an actionable error before init scaffolding. Back them up outside
`~/.pi/agent/extensions/` before retrying. Do not leave both entrypoints enabled.
Existing conflicting backups and malformed receipts are never overwritten.

## Limits and rollback

File publication is staged and checked, but is not one transaction across the
pair, receipt, legacy migration, or registered projects. An error can leave
partial earlier writes. Preserve the pair and receipt before manual recovery.
Detected concurrent edits abort rather than overwrite the changed file.

The checkpoint extension remains init-only; this release does not add checkpoint
refresh to update. Deterministic checks, hard denials, privacy rules, routing
limits, and classifier thresholds are unchanged.

To disable Jev auto, remove its two installed source files and reload Pi. Keep
the receipt so refresh preserves that removal. Another explicit init can restore
recognized missing files. To roll back the binary, run
`lgtm update --version v0.14.0`; the older binary does not manage the new bundle,
so disable it separately if needed. Keep your own matching hook backups.

## Verification

The seven notice-producer scenarios are now separate integration tests. Cargo
can run these isolated processes in parallel instead of one serial loop. Every
scenario, assertion, private workspace, and deadline is retained. Repository
command limits and the five-minute Pi pre-commit budget are unchanged.

The packaging checks run a copied binary in an empty work directory with an
isolated HOME. They cover all init modes, fresh and absent HOME refresh, offline
already-current update, read-only checks, idempotence, ownership, removal,
receipts, legacy migration, unsafe paths, and concurrent refresh. A separate
check loads the installed pair and exercises routing and gate notices with
deterministic provider stand-ins. These checks make no paid provider calls and
do not certify live provider behavior.

See [the Jev auto guide](../jev-auto.md) for runtime behavior and recovery.
