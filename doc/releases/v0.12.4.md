# v0.12.4

## Pi package defaults

LGTM no longer pins its default Pi packages to old versions. New project setup
uses unpinned npm names. The default list now also includes:

- `pi-web-search` for provider-backed web search.
- `@narumitw/pi-github-pr` for GitHub pull request status.
- `@narumitw/pi-goal` for explicit goal sessions.

Installing a package does not supply its credentials or start a goal.

## Migrate existing projects

Run:

```sh
lgtm update
# In each trusted project whose packages you want to update:
pi update --extensions
```

LGTM refreshes registered project settings. Pi downloads and installs the
packages. LGTM does not run npm or install package code. Restart Pi or use
`/reload` after package updates.

Init and refresh remove only the seven exact package pins shipped by LGTM
through v0.12.3. Other versions remain unchanged. Object-form package entries
keep their filters and other fields. Missing defaults are added without adding
a second entry for an existing package. Repeated refresh is idempotent.

A project package entry overrides the global entry for that package. Removing
the old project pin lets Pi update it instead of staying on the old version.
Global init does not add the project package list to global settings.

## Limits and rollback

LGTM cannot distinguish an old generated pin from an identical version selected
by the user. Both migrate. Different custom pins remain unchanged.
Unpinned packages can receive breaking changes and run with your user permissions.
Review updates before granting project trust. To roll back, select a known-good
package version and use Pi to reconcile it. The old exact LGTM default pins will
be migrated again by this release.

No new claim is made about native Pi hook verification, classifier routing, or
codemode enforcement. The runtime verification limits from v0.12.3 still apply.
