# v0.9.0

## What changed

- Add verified Pi 0.84.2 adapter support alongside the existing Claude and Codex adapters.
- Add project and global Pi extension installation through `lgtm init --agent pi` and `lgtm init -g`.
- Verify Pi built-in tool provenance and schemas before applying shared `bash`, `edit`, and `write` policy enforcement.
- Add runtime trust, attestation, session-bound evidence, bounded transport failures, and truthful fail-open reporting.
- Integrate Pi read-result guidance with the shared M20 path-scoped selector and persistent per-session deduplication.
- Preserve original Pi tool-result content and fields while appending applicable guidance.
- Add collision-safe extension upgrades, rollback backups, Pi 0.84.2 contract fixtures, and cross-platform integration coverage.

This release covers M23.1–M23.7. System-prompt placement measurement (#28/M23.8) and the final documentation drift suite (#29/M23.9) remain follow-up work.

## Affected users

Pi users can initialize a repository extension with:

```sh
lgtm init --agent pi
```

For machine-wide setup, use:

```sh
lgtm init -g --dry-run
lgtm init -g
```

Pi path-scoped guidance is available after a verified `read` result. Direct-first
`edit` and `write` calls remain policy-enforced but do not receive verified
path-scoped guidance before execution.

## Upgrade and compatibility

No migration is required. Update the binary, then initialize the desired Pi scope.
Existing Claude and Codex installations and behavior are preserved.

Pi sessions downgrade to an unverified state when the extension, runtime marker,
attestation, policy, trust decision, built-in provenance, or tool schema cannot be
verified. Custom, MCP, provider, overridden, and schema-mismatched tools are not
claimed as verified built-ins.
