# v0.4.0

## What changed

- Added a binary-free rules mode under `templates/claude-rules/`. Copying these
  files into a repository carries the standards into Claude Code with no install
  step, using native `.claude/rules/` path-scoped rules that load only when a
  matching file is read.
- An elapsed waiver expiry now marks that waiver inactive instead of rejecting the
  whole waivers file. Previously a single stale entry failed the load and silently
  disabled every hook.
- Writes to a file inside a directory that does not exist yet are no longer denied
  as a path escape.
- Claim verification is limited to executables the repository actually configures,
  so prose containing backticked identifiers can no longer create claims that no
  evidence could satisfy.
- Workspace discovery skips `fixtures` and `testdata` trees, which were being
  registered as real workspaces and gated with required commands.
- The bundled Python example declares its `src/` layout on the pytest path so its
  tests collect.

## Affected users

Anyone whose repository stopped enforcing after a waiver expired should upgrade;
that state was silent. Run `lgtm update`, then regenerate configuration if your
repository contains fixture or testdata trees:

```sh
mv .lgtm/config.json .lgtm/config.json.bak
lgtm init
```

Compare the workspace list before deleting the backup. Repositories without
fixture trees need no configuration change.

Waivers that have already elapsed will stop applying, so any rule one was
suppressing becomes enforced again. Review `lgtm report` after upgrading.

To adopt the rules templates without installing the binary:

```sh
cp templates/claude-rules/CLAUDE.md /path/to/repo/CLAUDE.md
cp -r templates/claude-rules/rules /path/to/repo/.claude/rules
```

These files are guidance, not enforcement. Controls that must hold regardless of
what an agent decides still require the hooks that `lgtm init` installs.
