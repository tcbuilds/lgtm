# v0.10.0

## What changed

- Bound nested workspace discovery and added fail-closed handling for common `.gitignore` literal, wildcard, anchored, directory-only, and negated rules.
- Keep warning-severity `PostToolUse` findings as non-blocking review feedback while error-severity findings remain blocking.
- Bound release transfers and clean descendant processes during self-update and secret scanning.
- Bound and align context and path-signal handling so policy consumers receive consistent, safe inputs.
- Render coverage evidence in reports for clearer command and threshold results.

## Affected users

All users receive tighter resource bounds and safer failure behavior during workspace discovery, self-update, secret scanning, context processing, and reporting. Projects with nested workspaces can now have supported `.gitignore` rules applied during discovery without additional configuration.

Warning-level policy findings no longer block the completed tool call; they remain visible as actionable review feedback. Error-level findings continue to block as before.

## Upgrade and compatibility

No migration is required. Replace the existing binary with the `v0.10.0` build. Existing Claude, Codex, and Pi installations and configuration formats remain compatible.

Unsupported, malformed, oversized, or unrepresentable inputs remain fail-closed or unverified rather than being treated as trusted data.
