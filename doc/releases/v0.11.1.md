# v0.11.1

LGTM v0.11.1 fixes repeated Pi hook warnings caused by runtime verification expiring during normal sessions.

## Fixes

- Remove the arbitrary ten-minute runtime attestation expiry. An otherwise valid Pi session remains verified after hours or days, without a renewal timer.
- Preserve executable and extension integrity checks, version checks, policy validation, trust and tool-contract checks, session identity, and runtime marker proof. Future-dated attestations remain unverified.
- Include the previously unreleased runtime-marker lookup repair and unsupported-tool filtering from commit `848b865`.

This release fixes age-related warnings; it does not suppress warnings for other hook failures or guidance-selection problems.

## Upgrade

Install v0.11.1, then regenerate the Pi extension in each initialized repository using the installed binary:

```sh
lgtm init --agent pi
```

Restart Pi afterward so its loaded extension and runtime proof match the new binary. No evidence schema migration is required. Updating the binary alone invalidates the old binary digest until the extension is regenerated and loaded.

## Validation

Regression coverage checks valid attestations at the recorded timestamp, after ten minutes, after six hours, and after seven days. Separate coverage rejects future timestamps and preserves rejection of changed binaries, edited extensions, and mismatched session evidence.

The tag-triggered release workflow runs the full locked test suite and builds Linux musl and Intel macOS binaries with checksums before publishing.

## Rollback

Reinstall v0.11.0, regenerate the Pi extension with that binary, and restart Pi. Existing evidence formats remain compatible; the ten-minute expiry returns with the older binary.
