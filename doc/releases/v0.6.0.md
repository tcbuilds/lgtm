# v0.6.0

## What changed

- `lgtm init` now writes `.lgtm/execpolicy.json` with a default list of
  destructive command prefixes, and the generated Claude `PreToolUse` matcher
  includes `Bash`. Prohibited commands are refused before they run.
- The command policy is evaluated wherever a shell command is present. It was
  previously reachable only on `PermissionRequest`, so Claude Code sessions never
  consulted it.
- `lgtm init --rules-only --agent codex` writes `AGENTS.md`. It previously
  reported success while writing `.claude/rules/`, which Codex does not read.

## Affected users

This release closes a gap rather than adding an option. Before it, a fully
initialized repository refused nothing: `.lgtm/execpolicy.json` was never
created, so the prohibited-command list was empty; the `PreToolUse` matcher was
`Edit|Write`, so shell calls never reached the hook; and the check itself was
gated to an event Claude Code does not send. Piping an `rm -rf /` payload at an
initialized repository returned allow.

Upgrade, then re-run init to pick up the policy and the widened matcher:

```sh
lgtm update
lgtm init
```

Existing files are preserved. An existing `.lgtm/execpolicy.json` is kept
byte-for-byte, and hook entries are merged without duplication.

The default prefixes cover `rm -rf` and its flag spellings, `git push --force`,
`git reset --hard`, `git clean -fdx`, `dd`, `mkfs`, `chmod -R 777`, and `shred`.
Matching compares whole argv elements from the start of the command, so
`git push --force-with-lease` remains allowed as the safe alternative, and a bare
`git clean -fd` is deliberately absent as ordinary cleanup. Edit the file to suit
your repository.

Treat this as a guardrail against an agent's obvious mistakes, not as a sandbox.
Prefix matching does not catch a prohibited command placed after a positional
argument, embedded in a compound shell line, or invoked through `sudo`.

Codex users who ran `--rules-only` against a previous release received no
guidance at all and should re-run:

```sh
lgtm init --rules-only --agent codex
```

Every standard is inlined into `AGENTS.md` because Codex has no path-scoped rule
mechanism, so the whole document enters each session. An existing `AGENTS.md` is
never overwritten.
