# v0.13.0 — 2026-10-18

LGTM v0.13.0 adds six advisory Jev tools for bounded file questions, diff-review
flags, scope and claim advice, diagnostic triage, compaction advice, and
untrusted-text warnings. The tools use Pi's native classifier API and existing
provider authentication. Managed Pi initialization installs them, but startup
does not make classifier requests. Deterministic LGTM enforcement remains
separate and authoritative.

This release follows v0.12.6 and includes the repair and verification work
merged in PR #126.

## What changed

- Added `lgtm_jev_files`, `lgtm_jev_review`, `lgtm_jev_scope`,
  `lgtm_jev_triage`, `lgtm_jev_compaction`, and `lgtm_jev_untrusted`.
  They return structured results and do not grant permission, change an
  enforcement gate, or verify a command claim.
- Read Pi's native structured Bash output and native read-tool context. Use
  guarded property access for native event data, and track changed paths with an
  independent NUL-delimited filename list. Rename detection is disabled, and
  text and external diff drivers are disabled. Recheck paths after reading a
  patch; hunk text and truncated displays are not complete filename lists.
- Use only governed read output. The tools make metadata-only source previews,
  check source stability, reject redirected or missing read bindings, and limit
  request files to 32 KiB and 1,500 lines. Output hashes describe authorized
  read text.
- Redact source metadata and excerpts before preview, provider transport, tool
  return, and optional Jev metadata persistence. Reject private-key input and
  common private credential paths, and handle quoted JSON credential
  assignments. Bounded credential scanning avoids overlapping backtracking
  patterns and keeps complete authorization schemes and tokens inside the
  redacted span.
- Accept valid fractional expected-index scores from Pi's native classifier.
  Handle unsupported runtime APIs and provider failures as explicit unavailable
  outcomes. Respect cancellation and timeout results instead of returning an
  advisory answer after cancellation.
- Share repeated privacy and transport code, classify integration fixtures as
  tests, and measure execution of rendered JavaScript fragments for SonarCloud
  LCOV coverage.

## Breaking change: advisory request inputs

The advisory tools no longer accept inline request bodies. Pass `requestPath`
to a bounded JSON file in the workspace. Do not pass raw excerpts, rubrics,
scope or claim data, or compaction state as inline arguments. `preview` and
`allowSend` are outer tool arguments; request-file contents cannot grant
permission. Diff review continues to use an empty argument object.

Prepare sensitive request files outside recorded tool arguments. Pi journals
nested arguments before a tool runs. A malformed inline call can therefore
still be recorded even if Jev rejects it, and moving content into a file cannot
erase earlier logs. Redaction is a conservative heuristic, not proof that
arbitrary text is safe. Treat request files and session logs as sensitive.

## Upgrade and rollback

Upgrade from v0.12.6 with:

```sh
lgtm update
```

Then run `/reload` in each running Pi session, or restart the session, so it
loads the updated extension. Running sessions do not adopt an extension update
until reloaded. Use `lgtm init --agent pi` once for untracked project hooks.

To roll back, run:

```sh
lgtm update --version v0.12.6
```

The older binary may refuse to refresh an extension generated by v0.13.0 because
it cannot recognize a future template digest. Before upgrading, retain a copy
of your v0.12.6 managed hook and settings. If rollback reports a refresh failure,
restore that known prior hook and run `lgtm refresh`; preserve custom settings
and do not force an overwrite of an unknown extension.

Then reload or restart each Pi session. These advisory tools require callers
to use the `requestPath` format; callers that used inline request bodies must
migrate before upgrading.

## Verification and limits

The merged PR #126 passed all PR checks and independent Sol-high and Astra-high
reviews. Verification reported 1,159 passing tests. The Jev rendered-JavaScript V8
report measured 98.57% line coverage and 84.89% branch coverage; these are not
whole-Rust-project coverage figures. SonarCloud reported 92.5% new-code
coverage and 0.0% new-code duplication. LCOV came from actual execution of
rendered JavaScript fragments.

These results do not claim that a new paid provider replay was run for the
repaired reference-input API, or that the full native interactive approval UI
was validated. Jev advice is not enforcement. Redaction cannot guarantee that
all arbitrary sensitive content is removed. Provider/runtime failures and
cancellation remain unavailable outcomes rather than approvals.

See [the Pi API and privacy guide](../adapters/pi.md#jev-advisory-tools-and-request-privacy)
for request bounds, safe input preparation, and migration details.
