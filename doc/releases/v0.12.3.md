# v0.12.3

## Pi updates and shared guidance

`lgtm update` can now find an older LGTM hook at the standard global Pi path,
`~/.pi/agent/extensions/lgtm.ts`, without a prior registry entry. The file must
match a known LGTM template and point to the running executable. Update replaces
the old active hook and uses the existing backup rules. It does not search other
repositories or replace custom hooks.

Global setup puts the same shared engineering guidance in
`~/.codex/AGENTS.md` and `~/.pi/agent/AGENTS.md`. It changes only an LGTM-managed
section. Your personal instructions remain. Older global registrations receive
the Pi section once. After migration, removing that section is an opt-out.
Migration state is saved even when all files are already current.

Pi setup also adds `+codemode` beside the existing tools. Global setup uses
`~/.pi/agent/settings.json`; project setup uses `.pi/settings.json`. Refresh
updates existing settings while the LGTM hook is present. Explicit opt-outs,
including an empty tool list, `-codemode`, and `-builtin:codemode`, remain in force.
This does not change your chat model or configure a classifier account.

## Safer evidence and Ruff checks

- Stop checks do not reuse evidence when source reads or path scans are uncertain.
  Digest checks detect changes made by scanners and configured commands.
- Staged commits still get a fresh assessment. Source scanning stays complete;
  this release does not restore the old source-file count cap.
- Ruff scans and version probes use bounded process transport and output capture.
  Capture failures and uncertain cleanup cannot produce a verified clean result.
- Linux containment keeps caller cancellation and detached-child cleanup. Its
  evidence contract is now `linux-isolated-subreaper-v5`.
- Unsupported platforms report unverified command containment. Waivers do not
  turn an unverified check into a verified result.

## Upgrade

Run:

```sh
lgtm update
```

An already-current update also refreshes managed files. If you replace the binary
by another method, run `lgtm refresh`. Versions through v0.12.1 do not run refresh
after the first upgrade; run it once after installing the new binary.

Untracked project installations still need their original `lgtm init` command
once. Register only the adapters you use. Removed hooks stay removed. Customized
or repointed hooks stay unchanged. A backup collision stops the refresh rather
than overwriting your file. Fix the reported problem, then run `lgtm refresh`.
The upgraded binary remains installed if refresh fails.

Reload or restart running agents after an update. Changes on disk do not replace
hooks already loaded in memory.

## Verification limits

Local validation covers formatting, strict Clippy, locked tests, build, policy
validation, and secret scanning. CLI checks cover migration, backups, shared
guidance, settings, and opt-outs. A copy of an actual older global Pi hook was
also migrated in an isolated home directory. The release workflow runs tests and
builds on Linux and Intel macOS before it publishes the archives and checksums.

These changes do not prove native Pi 1.1 hook compatibility, native approval UI
behavior, or enforcement of codemode calls. Do not suppress an unverified warning
without checking its runtime evidence. Existing filesystem race limits remain.

## Rollback

Reinstall v0.12.2 and restore the required managed files from backups or version
control. An older binary does not automatically undo new guidance or settings.
Add `-codemode` to disable codemode. Remove the Pi managed guidance section after
migration to stop its refresh. No dependencies were added, and repository policy
and command configuration are not rewritten.
