# v0.11.0

LGTM v0.11.0 makes agent setup more complete and predictable. `lgtm init` now installs the supported Claude and Pi project configuration alongside LGTM’s enforcement hooks, while preserving existing user choices and custom routes.

This release also updates Pi runtime attestation for Pi 0.84.3 and keeps upgrades from v0.10.1-generated Pi adapters ownership-safe.

## Highlights

- Claude initialization adds official language-server plugins and protected-file permission rules.
- Pi initialization installs package and language-server configuration from embedded templates.
- Existing agent configuration is merged instead of replaced.
- Malformed configuration stops initialization before any files are written.
- Pi 0.84.3 tool contracts are recognized without weakening structural verification.
- Existing v0.10.1 project and global Pi adapters can upgrade normally.

## What changed

### Claude project configuration

Running `lgtm init` for Claude now merges the supported project settings into `.claude/settings.json`.

The generated settings include:

- Official language-server plugin enablements for C/C++, Go, Java, Kotlin, Lua, PHP, Python, Rust, Swift, and TypeScript.
- Protected-file permission rules for lockfiles, Terraform state backups, package lockfiles, and local settings files.
- The existing LGTM lifecycle hooks.

The merge is additive and deterministic. Existing top-level settings, unrelated permissions, custom hooks, and explicit plugin disablements remain authoritative. Re-running init does not duplicate managed entries.

### Pi project configuration

Running `lgtm init --agent pi` now manages three project resources:

- `.pi/extensions/lgtm.ts`
- `.pi/settings.json`
- `.pi/pi-lsp.json`

The Pi settings template enables the supported project packages, including Pi LSP and the configured development extensions. Package identity matching recognizes pinned and unpinned npm forms, so an existing package version or filter remains unchanged rather than being duplicated.

The Pi LSP template provides named routes for commonly used language servers. Existing server definitions win by name, custom routes remain in place, and an existing timeout remains unchanged. Projects using the older top-level server-map shape are upgraded to the current wrapper shape during the merge.

Language-server executables are still installed separately. Init configures routes but does not download or launch language servers.

### Transactional validation

Agent configuration is now validated during init preflight.

Initialization returns a path-specific error when:

- A Claude settings root or managed section has the wrong JSON shape.
- Pi package entries are not strings or objects with a string source.
- Pi LSP server definitions have invalid command or extension fields.
- A Pi LSP timeout is not a positive number.

Validation occurs before output directories or files are changed, keeping failures transactional. Dry-run mode applies the same validation without writing files.

### Pi 0.84.3 compatibility

The Pi adapter now targets Pi 0.84.3. Its strict tool-contract verification accepts the optional descriptive field Pi 0.84.3 adds to array schemas while continuing to reject unknown structural changes.

A captured Pi 0.84.3 provenance fixture covers the supported tool contracts. Runtime payloads report successful contract verification when the live SDK matches those contracts.

The ownership allowlist includes both project and global v0.10.1 Pi adapter templates, so existing generated adapters can be replaced during a normal upgrade without treating them as user-authored collisions.

## Affected users

Claude users receive the managed plugin and permission entries the next time they run `lgtm init`.

Pi users receive project package and LSP configuration the next time they run `lgtm init --agent pi`. Existing package pins, package filters, custom settings, timeouts, and named server definitions remain in control.

Projects with malformed managed configuration must correct that JSON before init can continue. LGTM reports the affected path and reason instead of replacing the file.

## Upgrade and compatibility

No data migration is required. Replace the existing binary with the v0.11.0 build and rerun init for the agent configuration you want to update:

```sh
lgtm init
lgtm init --agent pi
```

Existing policy configuration, evidence formats, Claude hooks, Codex hooks, and supported Pi hook envelopes remain compatible.

Pi packages run with Pi’s process permissions. Review project package entries before trusting an unfamiliar repository. Pi also requires project trust before loading project-scoped packages and extensions.
