# v0.7.0

## What changed

- `lgtm init` now installs the rule files alongside the hooks. Plain init and
  `--rules-only` were previously mutually exclusive, so a default installation
  registered hooks with no guidance source at all.
- A rule's prose and its machine fields live in one file. `policy/rules.json`
  and the aggregate standards document are retired, and the 105 cross-references
  that bound them are deleted rather than repointed.
- The changed-test gate classifies source and test files across Rust,
  TypeScript/JavaScript, Go, Java/Kotlin, C#, and C/C++ in addition to Python.
  It reports `unverified` rather than blocking when it finds no association.
- Prohibited commands are matched by shape rather than by token prefix.
  `rm -r -f`, `rm --recursive --force`, `sudo rm -rf`, and `chmod 777 -R` were
  all allowed by v0.6.0 and are now denied.
- Deny reasons redact values carried by wrapper tokens, so a denied
  `env API_TOKEN=... rm -rf` no longer writes the credential into the hook
  response.
- A tests-passed claim requires whole-token matching with an ordered, nearby
  pass word. `latest`, `bypass`, and a `test` command listed beside an unrelated
  PASS column no longer raise a claim the Stop window cannot prove.
- `lgtm init` no longer refuses to run when a symlink lies on the path used to
  reach the repository. The guard against writing out of the repository walked
  ancestors to the filesystem root, so a symlinked home, work, or temporary
  directory blocked the install outright.

## Affected users

Two changes alter behavior you will notice.

**`lgtm init` writes rule files.** A default installation now creates 30 files
under `.claude/rules/`, including `standards.md`, 21 domain and language
documents, and 8 pattern documents. Rule installation joins the existing
preflight and staged-write transaction: it refuses to follow a symlinked
destination and leaves the repository untouched when any target cannot be
written.

Installations generated by v0.5.0 or v0.6.0 are recognized and updated rather
than mistaken for local edits. Adding frontmatter changed every shipped
template, so without migration every clean file would have been classified as
user-edited and never updated, stranding the installation on stale rules while
the hook injected fallback guidance on top. A file you have actually edited is
still preserved.

Upgrade and re-run init to pick up the rule files:

```sh
lgtm update
lgtm init
```

**The changed-test gate reports instead of blocking.** Where v0.6.0 required a
changed test file for Python source, the gate now covers seven language packs
and matches a source file to a test only within the same workspace boundary and
language pack. It no longer fails a Stop when it finds no association; it
records `unverified`.

This is a deliberate downgrade of a hard verdict. The evidence model has four
documented false-pass paths — exclusion computed from an order-dependent merge
of cached and unstaged status, rename source paths never excluded, an unparsable
diff header treated as an untracked whole-file change, and an attribute between
`#[cfg(test)]` and `mod` hiding an inline-test edit. Each is named in
`doc/test-association-gate.md` with a drift test. The gate now says only what it
can prove: a found association passes, a missing one is unverified. If you
relied on it to block, treat the signal as advisory until the evidence model is
redesigned.

**Command matching is stronger but is still not a sandbox.** Policy entries and
candidate commands are reduced to an executable, a flag set, and ordered
operands; the entry's flags must be present in any spelling and its operands
must lead. Leading privilege and environment wrappers are peeled before matching
and named in the deny reason. Equivalence is reconciled at compare time rather
than by expanding aliases, so `-r` and `-R` never become interchangeable — they
are synonyms for `rm` but different options for `ls`. A multi-character token is
split only when every character is a known boolean short option for that
executable, so `git push -ofoo` carries a push option, not a force flag.

`git push --force-with-lease` and a bare `git clean -fd` remain allowed by
assertion, since blocking either would be worse than the bypass this closes. The
residual evasion surface is documented rather than claimed closed.

**Init works under a symlinked path again.** The preflight that stops a write
from escaping the repository through a symlink placed inside it was walking
every ancestor up to the filesystem root, so any symlink on the way *to* the
repository was refused as though it were an escape. `/var` and `/tmp` are
symlinks on macOS, and a symlinked home or work directory is common elsewhere.
The walk now stops at the repository root. A symlinked destination inside the
repository is still refused, and both directions carry a test.

## Upgrade and compatibility

No configuration format changed. `.lgtm/config.json` stays at version `2`, and
an existing `.lgtm/execpolicy.json` is kept byte-for-byte. Hook entries are
merged without duplication.

Repositories that consumed `policy/rules.json` or the aggregate standards
document from a checkout must read the rule files under
`templates/claude-rules/rules/` instead. `lgtm policy export` continues to emit
a derived `rules.json`, and its bundle digest and export are fed by one shared
function so they cannot diverge.

A `.gitattributes` enforcing LF is now checked in for the files feeding
`include_str!` and the digest table. A CRLF checkout previously yielded a
zero-rule registry.
