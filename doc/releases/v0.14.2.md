# v0.14.2 — 2026-10-19

This release makes old flat Jev extension migration part of `lgtm update`.
v0.14.1 could install the new bundle, but refused older or edited flat files.
That left some users with an updated binary and a failed managed-file refresh.

## Upgrade

```sh
lgtm update
```

The updater backs up readable regular legacy source files at:

```text
~/.pi/agent/extensions/jev-auto.ts
~/.pi/agent/extensions/jev-auto-gates.ts
```

It preserves their exact bytes under
`~/.local/state/lgtm/jev-auto/legacy/`, removes those old files from extension
discovery, and installs the current embedded pair:

```text
~/.pi/agent/extensions/jev-auto/index.ts
~/.pi/agent/extensions/jev-auto/jev-auto-gates.ts
```

Then use `/reload` in Pi. No manual move, source checkout, or copy is needed for
this legacy migration. You do not need a separate refresh command after a
successful update. An already-current update, refresh, and all init modes use
the same migration rules. `update --check` and init dry-runs remain read-only.

## Backup rules

- Older or edited sources, complete pairs, and either legacy file on its own
  can migrate. Old custom code is saved, not merged into the current extension.
- An identical backup stays unchanged.
- A different fixed-name backup is preserved. LGTM uses a hash-suffixed sibling
  name for the new backup instead of overwriting it.
- All needed backups are published before either legacy source is removed.
- The update reports where it saved the legacy files.

Backups are outside Pi extension discovery. New backups receive private Unix
permissions; identical existing backups keep their contents and permissions.
They are not a second enabled copy of the extension. Migration never executes
old source files or calls a provider.

## Safety and limits

Unsafe symlinks, special files, unreadable or invalid source text, malformed
receipts, or contradictory backup contents still fail safely. Custom sources
in the newer `jev-auto/` directory keep their ownership protection. Migration
will not silently replace that custom directory or create duplicate entrypoints.
Existing receipt-tracked removals remain preserved during refresh.

Publication is staged and checked for detected concurrent edits. It is not one
transaction across backups, sources, receipts, or registered projects. An error
can leave partial earlier writes; follow the reported recovery steps and keep
the backups. Classifier access is still a runtime requirement, not an installer
requirement. Deterministic checks, hard denials, and resource limits are unchanged.

## Rollback

To roll back the binary, run `lgtm update --version v0.14.1`. Keep the current
directory bundle and receipt. Do not restore flat files beside that enabled
bundle. The preserved old sources remain available for inspection or a separate,
explicit restoration after disabling the current bundle.

See [Jev auto setup](../jev-auto.md#install-and-verify) for runtime controls and
ownership rules.
