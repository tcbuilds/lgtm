# v0.15.1

This patch release removes dead Claude Code deny rules that caused startup
warnings, and replaces two retired Pi documentation packages with Context7.
It contains fixes only and no breaking changes.

## Changes

- Claude Code init now writes only the four `Edit(...)` deny rules for lock
  files, `*.tfstate.backup`, `package-lock.json`, and `settings.local.json`.
  Claude Code applies `Edit(path)` rules to every file-editing tool, including
  Write, MultiEdit, and NotebookEdit. It never matches path-scoped `Write(path)`
  rules, so the `Write(...)` twins that earlier releases also wrote protected
  nothing and printed four "Deny rule Write(...) never matches" warnings at
  startup.
- Init merges and managed refresh remove the four exact legacy entries:
  `Write(**/*.lock)`, `Write(**/*.tfstate.backup)`,
  `Write(**/package-lock.json)`, and `Write(**/settings.local.json)`.
- Pi setup no longer installs `npm:pi-mcp-extension` or `npm:rtfd-pi`. It uses
  Pi's built-in MCP support and adds the official `npm:@upstash/context7-pi`
  package for library documentation. Init and managed refresh remove existing
  `pi-mcp-extension` and `rtfd-pi` npm entries, including versioned and
  filtered entries, and add Context7 when it is missing.

## Affected users

- Anyone who ran `lgtm init` for Claude Code and sees "Deny rule Write(...)
  never matches" warnings when Claude Code starts.
- Pi users whose project or global settings list `pi-mcp-extension` or
  `rtfd-pi`.

## Upgrade

```sh
lgtm update
```

The updater refreshes registered project and global managed installations,
which retires the legacy `Write(...)` deny rules and migrates Pi packages. If you
replace the binary manually, run `lgtm refresh`. For a repository that is not
registered, run `lgtm init` in it once. Restart Claude Code to confirm the
warnings are gone. Restart Pi after the package change; tools already loaded in
a session can remain available until restart.

## Compatibility

- Protection is unchanged. The retained `Edit(...)` rules already covered every
  file-editing tool, including Write.
- Removal is exact-match only. Deny entries carry no ownership marker, so any
  other `Write(...)` rule you wrote yourself is preserved.
- The Pi migration preserves other packages and settings, local packages, and
  an existing Context7 version and its resource filters. It does not change MCP
  server configuration; reconfigure any server that used the old bridge with
  Pi's built-in MCP commands.
- Context7 works without an API key, with IP-based rate limits. For higher
  limits, set `CONTEXT7_API_KEY` in your shell, never in repository settings.

## Rollback

To restore the previous release, run `lgtm update --version v0.15.0`, then
reload or restart agents. That version writes the `Write(...)` deny rules again
on the next init. To restore a retired Pi package manually, use
`pi install npm:rtfd-pi` or `pi install npm:pi-mcp-extension`, adding `--local`
for project scope. A later init or managed refresh with v0.15.1 or newer removes
them again.

See [Pi documentation tools and MCP](../pi-packages.md) for package details.
