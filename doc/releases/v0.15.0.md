# v0.15.0

This release makes automatic LGTM hooks observers, not permission gates.
Checks stay available through an explicit `lgtm check` command or owner-configured
CI. This is a breaking change for users of the removed gate interfaces.

## Breaking changes

- Automatic hooks no longer deny commands, protect edit paths, intercept commits,
  request approval, or block task completion.
- Stop and subagent-stop events report without running configured verification
  commands. A `check: true` field does not turn automatic completion into a check.
- Post-tool findings provide nonblocking context after an operation has run.
- The guarded-commit CLI, commit parser, approval transactions, and shared adapter
  denial/approval/completion-veto responses are removed. Integrations that use
  those interfaces must move verification to an explicit check or CI.
- Init stops generating native Codex command bans. Init and managed refresh retire
  only LGTM-owned Codex command rules. User rules and host permissions remain.

## Explicit checks still report failure

`lgtm check` still runs requested verification. Actual error-level failures return
exit code 2; operational errors remain nonzero. Unavailable checks remain visibly
unverified. Automatic observer behavior does not turn a failed check into a pass.

Timeouts, bounded reads and execution, cancellation, process cleanup, secret
redaction, and optional Jev privacy controls remain. No permissive mode, waiver
layer, or replacement approval system is added.

## Upgrade

```sh
lgtm update
```

The updater runs the newly installed binary to refresh registered project and
global managed installations. No source checkout or per-repository patch is
needed. Reload or restart running agents afterward; use `/reload` in Pi.

Old unregistered installations need the appropriate `lgtm init` command once.
LGTM does not scan unrelated repositories for them. Unknown or customized Pi
extension files retain ownership protection; follow any reported repair steps
rather than overwrite them. If you replace the binary manually, run
`lgtm refresh` before reloading agents.

The updater retires LGTM-owned Codex rules during managed refresh. It does not
remove user-defined CI checks, native host permissions, sandbox rules, or another
application's risk controls.

## Verification scope and limits

Integration coverage checks nonblocking hooks, explicit failure exit codes,
Codex rule retirement, bounded file reads, and generated Pi runtime behavior.
The release workflow runs all-target, all-feature tests on Linux and macOS before
publishing binary archives and checksums.

Generated Pi hook editor type/lint diagnostics are not clean. Node syntax and
runtime fixtures are separate checks; they are not a strict TypeScript pass.
Automated fixtures also do not prove every live host/UI combination or paid
classifier quality. See [the removal record](../../removal.md) for validation
results and accepted proof limits.

## Rollback

To restore the previous release, run `lgtm update --version v0.14.2`, then reload
or restart agents. That version can restore LGTM's former automatic veto behavior.
Managed refresh still respects ownership checks and intentional removals; do not
assume a binary downgrade restores every file. Keep reported backups and restore
custom files only through a separate, explicit owner decision.

See [the architecture decision](../adr/0017-observer-hooks-and-explicit-checks.md)
for the observer/explicit-check boundary.
