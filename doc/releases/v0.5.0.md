# v0.5.0

## What changed

- Added `lgtm init --rules-only`, which installs the standards into
  `.claude/rules/` and registers nothing else: no hook entries, no `.lgtm/`
  directory, no repository configuration.

## Affected users

Existing installations are unaffected. `lgtm init` behaves exactly as before;
the new behavior is opt-in through the flag.

Use it when you want the standards as guidance without enforcement:

```sh
lgtm init --rules-only
```

Everything is written under `.claude/rules/`, so an existing `CLAUDE.md` at the
repository root is never modified. The entry document is installed as
`.claude/rules/standards.md` with no `paths:` frontmatter, which Claude Code
loads every session; the remaining files declare globs and load only when a
matching file is read.

Re-running is safe. A file whose contents match the shipped template is reported
as unchanged, and a file you have edited is kept and named in the output, so
local customization survives upgrades.

This mode installs guidance only. Claude Code treats these files as context
rather than enforced configuration, so anything that must hold regardless of what
an agent decides still requires the hooks that plain `lgtm init` installs.

The templates can also be taken without the CLI:

```sh
curl -fsSL https://github.com/tcbuilds/lgtm/archive/refs/tags/v0.5.0.tar.gz \
  | tar -xz --strip-components=3 -C .claude 'lgtm-0.5.0/templates/claude-rules'
```
