# v0.13.1 — 2026-10-18

LGTM v0.13.1 repairs the Jev file tools when a Pi guidance hook changes a tool
result. Pi 1.3 drops structured tool content when a later hook, such as
pi-rules, returns text only. Jev treated the missing field as a filtered read.
It then rejected a valid `requestPath` call or a safe selected file read.

This release follows v0.13.0 and includes the fix merged in
[PR #128](https://github.com/tcbuilds/lgtm/pull/128).

## What changed

- Jev now accepts one complete visible text block when `structuredContent` is
  missing. The block must be intact, and its SHA-256 hash must match the read
  binding digest. Jev does not join blocks or strip guidance text from a block.
- Jev still rejects anything it cannot verify. It never rereads raw source,
  never recovers removed text, and never overrides `structuredContent` when
  that field has a value.
  Changed bindings, removed or altered file blocks, and mismatched hashes are
  still rejected.
- The rule lives in the shared governed-read check. It applies to request file
  readers and to selected source file reads.
- Recognize the exact v0.13.0 project and global extension templates during
  upgrade. Create a backup if none exists; preserve an existing canonical backup.
  Custom hooks remain protected.
- This patch does not change any public API, dependency, or policy.

## Upgrade and rollback

Upgrade with:

```sh
lgtm update
```

Then run `/reload` in each running Pi session, or restart the session. A running
session does not load the new extension until it reloads. Use
`lgtm init --agent pi` once for untracked project hooks.

To roll back to v0.13.0, run:

```sh
lgtm update --version v0.13.0
```

An older binary knows only the extension template digests that shipped with it.
It may refuse to refresh an extension generated by v0.13.1. Before you upgrade,
keep a copy of your managed hook and settings. If the rollback reports a refresh
failure, restore that copy and run `lgtm refresh`; keep your custom settings and
do not force an overwrite of an unknown extension. Then reload or restart each
Pi session.

## Verification and limits

The fix passed 1,159 tests. `cargo fmt --check`, strict Clippy, and the build
also passed. A preview with the real Pi 1.3 SDK and pi-rules made zero classifier
calls. Independent Sol-6.1-high and Astra-high reviews found no blockers.

These results do not claim a new paid provider replay or full coverage of the
native interactive approval UI. Jev advice is not enforcement.

See [the Pi adapter guide](../adapters/pi.md#jev-file-questions) for the
governed-read rule and its limits.
