# v0.16.0

This minor release adds state and concurrency guidance and fixes the rule-path
matcher that decides which rules LGTM selects for a file. The new rules are
advisory: no new `must` rules, no new blocking checks, and no breaking changes.

## Changes

- New `state-and-concurrency.md` rule file covers implicit state machines,
  check-then-act races, idempotent and recoverable cross-system operations,
  lease fencing tokens, event ordering and duplicate delivery, and failure-path
  tests. It loads only for state, worker, job, queue, consumer, event, webhook,
  workflow, scheduler, outbox, lock, lease, retry, and polling paths.
- The embedded registry grows from 71 to 78 rules. All seven new rules are
  prompt-stage guidance with warning severity:
  - `should`: `check-then-act-atomicity`, `cross-system-idempotency`,
    `event-ordering-duplicates`, `state-failure-path-tests`.
  - `review`: `state-machine-review`, `lease-fencing-review`, and
    `business-rule-authority-review` (in `code-organization.md`), which asks
    that business rules be enforced where the data is authoritative, not only
    in a client or caller.
- Existing rule files gain pointers: `error-handling.md` asks for attempt or
  step caps plus an overall deadline on polling and agent or tool execution
  loops, and for idempotency keys on retried cross-system operations;
  `testing.md` asks for tests of invalid transitions, competing callers,
  retries, duplicate delivery, and failure between steps; `sql.md` points its
  check-then-act rule at the new file.
- The rule-path matcher no longer lets `**/X` match `X` in the middle of a file
  or directory name, and a brace option starting with `*` no longer leaks into
  its siblings (`{*a,b}` matched `xb`). Mid-name false positives are gone, for
  example `bios/` and `myandroid/` (mobile), `latest_version.py`, `contests/`,
  and `my__tests__/` (testing), `mydocs/` and `XREADME.md` (config), and
  `x.github/workflows/` (infrastructure).
- Real naming conventions the old matcher covered by accident are now explicit
  globs: `*.env.example` and `*requirements*.txt` (config, now including
  `dev-requirements.txt` and `requirements-dev.txt`), `*.Dockerfile*`,
  `*.dockerfile*`, and prefixed `*-docker-compose*.yml` (infrastructure, for
  example `api.Dockerfile`), `*_tests/` and `*-tests/` (testing), and
  `*_migrations/` (SQL).
- A new regression test proves `lgtm update` retires the legacy `Write(...)`
  deny rules that v0.15.1 removed. No behavior change.

## Affected users

- Everyone who installs LGTM rule files: refresh adds `state-and-concurrency.md`
  and replaces eight changed shipped files (`error-handling.md`,
  `code-organization.md`, `testing.md`, `config.md`, `infrastructure.md`,
  `sql.md`, `patterns/sql.md`, `patterns/testing.md`).
- Every agent that relies on LGTM's own rule selection: prompt fallback
  packets, pre-tool baselines, `lgtm` rule selection output, and Pi's read-time
  guidance injection. Files whose names only matched mid-name no longer receive
  those rules. Claude Code's native `.claude/rules/` `paths` loading uses its own
  matcher and is unaffected by the matcher fix.
- Codex users with a generated `AGENTS.md`.

## Upgrade

```sh
lgtm update
```

The updater refreshes registered project and global managed installations,
which installs the new rule file and replaces the changed ones. If you replace
the binary manually, run `lgtm refresh`. For a repository that is not
registered, run `lgtm init` in it once. Restart Claude Code, or `/reload` or
restart Pi, so running sessions load the new rules.

## Compatibility

- Each replaced rule file that differs from the new template is first saved as
  a content-addressed `.bak` beside it, as for every rule upgrade. Because eight
  shipped files changed, an untouched v0.15.1 install gains eight backups.
  Delete them once you have confirmed you do not need your earlier copies.
- A Codex `AGENTS.md` generated by v0.12.0 through v0.15.1 and never edited is
  upgraded by `lgtm init --agent codex`; an edited one is kept unchanged.
- No configuration, waiver, or override format changed. The new rules are
  overridable like other advisory rules.

## Rollback

To restore the previous release, run `lgtm update --version v0.15.1`, then
reload or restart agents. Its refresh restores the v0.15.1 copies of the eight
changed rule files, backing up the v0.16.0 copies first. Older releases do not
remove `state-and-concurrency.md`; delete `.claude/rules/state-and-concurrency.md`
if you no longer want it. For Codex, restore your saved pre-upgrade `AGENTS.md`
or remove the state and concurrency section; older init keeps an `AGENTS.md`
it does not recognize.
