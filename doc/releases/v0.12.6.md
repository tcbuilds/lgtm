# v0.12.6

## More stable Pi hook checks

LGTM accepts both current `builtin:read` paths and legacy `<builtin:read>` paths
for Pi built-in tools. Safe schema annotations, reordered required fields, and
added optional inputs no longer make the hook unverified. Changed required
fields, incompatible input types, unknown structural schema changes, and tools
from non-built-in sources still fail verification.

Repeated hook failures show one warning per reason per session. Each warning
includes a reason code and repair guidance. LGTM still attempts to record every
failure in session evidence; Pi persistence errors remain best effort. Late failures from an old session cannot suppress warnings in a
new session. Secret scans, runtime attestation, and commit approval checks remain
enabled. Bash-result tracking and tool-call IDs from v0.12.5 are preserved.

## Upgrade

Run `lgtm update`, then `/reload` or restart each running Pi session. The update
refreshes registered canonical hooks and can adopt a known canonical hook at the
standard global path. Customized, repointed, and disabled hooks are preserved.
Untracked project hooks need `lgtm init --agent pi` once.

This release recognizes the v0.12.5 hook templates and the earlier compatibility
fix build for upgrade. Publishing a release alone does not replace a loaded
extension. No Pi package update is required for this fix.

Tool-origin checks were probed against Pi 1.1.0. This is not a claim of support
for every future Pi version, custom tools, codemode enforcement, or native
interactive approval UI. See [the Pi adapter guide](../adapters/pi.md) for
compatibility limits, warning reasons, and rollback guidance.
