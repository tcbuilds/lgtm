# v0.12.1

LGTM now refreshes its shipped rule and pattern files on reinitialization instead
of skipping unrecognized content as "locally edited".

## Fixed

- Removed the 512-file repository source-scan cap. The upgraded binary scans all
  eligible files within the existing traversal and execution budgets; this fix
  requires no repository configuration or hook regeneration.
- Runtime artifact directories no longer consume the source-scan budget, and
  traversal-limit failures are no longer mislabeled as command timeouts.
- Pi cancellation and session shutdown terminate active hook processes. Linux
  command supervisors clean up command descendants when their caller exits.
- `lgtm init` replaces changed LGTM template files under `.claude/rules/`, including
  their current `description` and path-scoping frontmatter.
- `lgtm init --agent pi` also installs and refreshes that same rule catalog.
- Custom filenames remain untouched. Pi's managed `AGENTS.md` block and shared
  settings retain their existing merge behavior; Codex guidance is unchanged.
- Replaced content is saved beside each rule as `<rule>.<sha256>.bak`. Successive
  upgrades preserve distinct backups without blocking normal reinitialization.
  A conflicting backup is rejected rather than overwritten.
- Pi's Bash pre-tool timeout now leaves a 10-second margin over its fixed 300-second
  pre-commit gate budget; normal hook timeouts remain 10 seconds.

## Staged secret checks

Commit checks scan the Git index. Only eligible built-in heuristic findings can
request exact-content approval: Pi uses native confirmation with fresh
revalidation, and Claude Code uses native Ask with guarded execution. Provider,
private-key, custom, and unknown findings remain blocking.

Native Pi/Claude approval UI and Pi cancellation smoke tests remain pending.
Generated Pi extension TypeScript/lint diagnostics also remain unresolved. These
integrations are not an OS sandbox against same-user processes or concurrent Git
mutations. Automatic Pi extension migration after binary upgrades is not included;
refresh the extension and restart Pi as described below.

## Test infrastructure

Linux subprocess-cleanup tests now isolate and reap their intentionally orphaned
children, allowing the full suite to run under LGTM's command supervisor without
weakening production containment checks.

## Upgrade

Install v0.12.1, then run the appropriate command in your repository:

```sh
lgtm init
# Or, for Pi:
lgtm init --agent pi
```

LGTM's shipped filenames are managed output: edits to those files are backed up
and replaced. Put custom guidance in separately named rule files. Use `--dry-run`
to preview rule replacements. Restart Pi after refreshing its extension.

No new dependencies or evidence schema migrations are introduced. Backup files
contain the previous rule text; review them before committing them to a repository.

## Validation

Regression tests cover replacement of edited rules and missing descriptions,
custom-file preservation, repeated initialization, successive backups, backup
collisions, dry-run preservation, and unchanged Codex behavior.

The full locked test suite, formatting, strict Clippy, build, and embedded policy
validation passed locally, including a regression scanning 1,024 source files.
Automated extension tests cover cancellation, shutdown, and approval revalidation;
they do not replace the pending native UI checks.

The tag workflow runs the locked test suite and builds Linux musl and Intel macOS
archives with checksums before publishing.

## Rollback

Reinstall v0.12.0 and restore any required previous rule content from the adjacent
`.bak` files or version control. Older init preserves unrecognized rule content;
it will not automatically undo these replacements.
